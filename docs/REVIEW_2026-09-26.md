# Warlords — Fresh-Eyes Review, 2026-09-26

**Scope:** every doc listed in CLAUDE.md's reading order, the code in `scripts/`, `data/`, `tools/`,
and a run of every harness plus one scripted sortie. Non-authoritative. Tags: **observed** (I ran it
and saw it), **read** (from source), **guess** (inference).

**How it was run.** Godot **4.7.1** Linux headless (the same version as your editor), on a copy of
the working tree taken at `8d02fc4` + your uncommitted `project.godot`. The copy left out the gitignored
`addons/limboai` and `addons/ziva_agent`, so it matches a clean clone rather than your machine
(see 2.10). The godot_mcp bridge needs the editor-side MCP server, so it was not used. The "play session"
is a throwaway scene (not committed) that calls the same entry points the UI does: the recruit
button, the escort toggle, click-to-move along an A* route, the site action and choice sheet,
and the automatic deposit and death paths. No mouse and no rendering were involved.

## 1. Verdict

1. R2a–R2d are built, and every harness is green: 1,712 assertions across 10 scenes, 0 failures, all travel rows in band, and `verify_combat_feedback` clean 15 times out of 15. CURRENT_STATE.md (2026-08-09) still says "Nothing in R2 is implemented."
2. The loop R2 was built to prove does not close in play. A corpse raised at a grave never becomes a unit (**observed**: escort 3 → 3). The R2d write-up's "a skeleton raised at a grave joins with no extra code" was only ever tested by adding a `Worker` by hand.
3. Death still heals him at the Throne and play continues. The legacy crusade can still be reached through grave notice, and timed recruitment still fires, so an R2 exit playtest today would be measuring a game with no failure state.
4. R2e (the Raven) has not started. It depends on camp occupancy, which R2a never built.
5. LIVING_WORLD L0 is further off than the spec suggests: stockpile, population and Power all live in `GameState`. With ruling 9 (no starting skeletons), the player currently has **no way to get any undead at all**.

**What §5.2 would replace (read).**
- Two production paths exist today: a passive building tick (only the Bone Pile, 2 bones / 5 s) and the worker trip loop (distance, per-unit effective skill, carry = Endurance, node depletion, threshold fall-through).
- Jobs are **not attached to buildings**: skeletons chop wood with no Woodcutter.
- `base × staffed × integrity` therefore has nothing to multiply for the player. It also conflicts with §5's own "agents *walk out*".
- The analogues are `Building.hp/max_hp` for integrity (only the Throne has any, and there is no repair) and Barracks `capacity` for slots.
- Cheapest faithful reading: the formula as a **multiplier on the trip loop's yield**, with the Throne hosting unlimited gatherer slots. "Runs unchanged" then holds (ruling 7.6).

## 6. Recommendations (opinionated, in order)

1. **One "R2 close-out" prompt: 2.1, 2.3, 2.4, 2.7, 2.8, 2.9, plus 2.6's gate (~8–10 h).**
   - Why first: every one is small, and together they are the difference between "R2d landed" and "the sortie loop is real".
   - 2.1 is also L0's hard prerequisite.
   - Make its harness raise a corpse **through `begin_action`**, not `add_worker`, so the fake that hid 2.1 can't recur.
2. **R4-lite before R2e (~8–12 h).** Death ends the run, a summary, restart. Own or delete `game_won`/`game_lost`/the crusade. Reset `time_scale`.
   - Why: CURRENT_STATE §5 puts R2e first and LIVING_WORLD §14 puts R4-lite after. Both orders measure R2's exit ("dying is traceable to a decision") without death meaning anything. You would be tuning risk against a game that has no cost to failure.
   - This is the one place I'd reorder CURRENT_STATE §5.
3. **R2e with 2.5 folded in (~12–16 h):** occupancy roll, discovery flag, camp table per ruling 1, then the Raven as specced.
   - Why not skip it: it is fully specced, it is the cheapest "reason to leave" you have, and the honesty harness is good discipline for L2's witnesses.
   - If ruling 7.8 says R3 folds into LIVING_WORLD, still do R2e. The Raven is independent of both.
4. **The R2 exit playtest, with the §14 questionnaire and the deferred combat-feel questions.** Only now does it measure something.
5. **Fold R3 into LIVING_WORLD L2** (ruling 7.8).
   - R3 = reputation axes + recruitment driven by notoriety. L2 = guild standing + witness runners + the Known trigger.
   - These are the same "the world noticed" machinery built twice. Build the witness runner once, feed both standing and the deeds ledger from it, and add the axis thresholds on top.
   - I think LIVING_WORLD §14's "alongside R3" understates the overlap.
6. **L0, scoped as "GameState becomes a façade over `settlements[player]`"** (rulings 7.5/7.6), not a rewrite. Then L1 only after ruling 7.7.
7. **Demo shell last:** Input Map, a pause + title scene, export preset, strip the MCP autoloads and the time-scale button from release, minimal SFX (~15–25 h). None of it teaches you anything about the game.
8. **Docs:** delete CURRENT_STATE.md rather than refresh it (ruling 7.4), slim CLAUDE.md, and fix the history record for 2.1. A snapshot doc has now been wrong for seven weeks; CLAUDE.md's "Current phase" and this review cover it.
